# Server domain and integrations

Next route handlers call these modules. `auth.mjs` verifies Firebase sessions, staff access and mutation origins. `policy.mjs` allowlists services/methods and role permissions, including optional MFA for privileged roles (`CMS_REQUIRE_MFA_ROLES`). `execute.mjs` runs the server domain pipeline. `domain.mjs` reuses the tested repository invariants in an isolated in-memory transaction engine. `persistence.mjs` persists changed documents in revision-checked Firestore transactions. It also reuses a warm instance's workspace while the stored revision is unchanged (`createPersistence`). `firebase.mjs` can target a restored database with `FIRESTORE_DATABASE_ID`.

`publication.mjs` projects published content and referenced media only, through the field allowlists in `public-fields.mjs`. Disabled stays become a minimal summary on the tours that name them. `public-feed.mjs` serves `/api/public/*`: it sanitises stored documents on read and pages the catalogue deterministically. `public-reconcile.mjs` (run with `npm run public:reconcile`) rebuilds `cms_public`, dry run first.

`media.mjs` inspects image bytes and dimensions and uploads to Cloudinary. `booking-sync.mjs` imports website requests: a recent window, a resumable sweep and bounded, idempotent imports. `email.mjs` runs the Resend outbox: due-first selection, leases, the idempotency window, and delivery state that only moves forward. The verified webhook route records events through `recordEmailEvent`. `scheduler.mjs` runs scheduled jobs independently, with redacted, correlated results. `diagnostics.mjs` streams responses above the buffered platform limit and logs sizes only. Staff access records are distinct from published team profiles and the editorial staff directory.

`tests/*.test.mjs` run without cloud credentials. `tests/support/fake-firestore.mjs` is an in-memory Firestore double for persistence, feed, booking and email tests. Browser contract tests inject isolated test persistence into the same execution pipeline; production routes never accept a persistence override or a demo identity. Live integration verification requires staging configuration. See [docs/PRODUCTION_READINESS.md](../docs/PRODUCTION_READINESS.md).
